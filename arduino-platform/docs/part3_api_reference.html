3.1 Pin Numbers Are Per-Device — Read This First

The worked examples further down this page use dsPIC33CK32MP102 pin numbers. That was the first device this platform supported, and its numbers were left in the examples as if they applied everywhere. They do not. The table below is generated from the pins_arduino.h of each variant — the same file the compiler reads — so where an example below and this table disagree, the table is right.

The fix in your own sketches is to use the names in the left-hand column instead of raw numbers. LED_BUILTIN, A0, SDA, SCL and PIN_SPI_SCK each resolve to the correct pin for whichever board is selected under Tools > Board, so the same sketch compiles for all four. dsPIC33CK256MC005 is this platform's priority device and is the first column.

Complete pin maps: Part 2 has the pad-by-pad table for the dsPIC33CK256MC005 Curiosity Nano (§2.2) and for the dsPIC33CK32MP102 (§2.4).
Three dsPIC33CK256MC005 pins are not free. D10 (RB5 = PGD3) and D11 (RB6 = PGC3) are wired to the on-board nEDBG debugger; driving them from a sketch fights the debugger and can cost you the COM port. D38 (RD13) is the SW0 button and has no ADC channel, so analogRead() on it returns noise. Pins D2-D4 are RA2-RA4 on all four devices, which is why the examples on this page use them.

3.2 Digital I/O Functions

pinMode()

void pinMode(uint8_t pin, uint8_t mode)

Configures a pin as input or output.

ParameterValuesDescription
pin0 to NUM_DIGITAL_PINS - 1Arduino pin number. The top of the range is device-specific — see §3.1.
modeINPUTHigh-impedance input (TRIS=1)
OUTPUTPush-pull output (TRIS=0)
INPUT_PULLUPInput with internal pull-up enabled (CNPU)
// Example: Configure pin D0 as output, D2 as input with pull-up
pinMode(0, OUTPUT);        // RA0 = output
pinMode(2, INPUT_PULLUP);  // RA2 = input + pull-up resistor (~40K to VDD)
How it works internally: Sets TRISx register (direction), CNPUx register (pull-up), and clears ANSELx bit (forces digital mode on analog-capable pins).

digitalWrite()

void digitalWrite(uint8_t pin, uint8_t val)

Sets a digital pin HIGH (3.3V) or LOW (0V).

ParameterValuesDescription
pin0 to NUM_DIGITAL_PINS - 1Arduino pin number. The top of the range is device-specific — see §3.1.
valHIGH (1)Pin outputs 3.3V
LOW (0)Pin outputs 0V (GND)
// Example: Turn LED on and off
digitalWrite(LED_BUILTIN, HIGH);  // drive the pin to 3.3V
delay(500);
digitalWrite(LED_BUILTIN, LOW);   // drive the pin to 0V
How it works: Writes to LATx register (not PORTx) to avoid read-modify-write issues.
On the dsPIC33CK256MC005, HIGH turns the on-board LED off. LED0 is wired between VDD and RD10, so the pin sinks the current and LOW lights it (LED_BUILTIN_ACTIVE_LOW is defined in that variant's pins_arduino.h). A blink sketch still blinks — only the phase is inverted — but a sketch that lights the LED to signal an event needs LOW, not HIGH.

digitalRead()

int digitalRead(uint8_t pin)

Reads the state of a digital pin.

ParameterDescription
pinArduino pin number, 0 to NUM_DIGITAL_PINS - 1 (§3.1)
ReturnsHIGH (1) if pin voltage > ~1.5V, LOW (0) otherwise
// Example: Read a button (active-low with pull-up)
pinMode(2, INPUT_PULLUP);  // Button on D2, connects to GND when pressed

void loop() {
    if (digitalRead(2) == LOW) {
        // Button is pressed!
        digitalWrite(LED_BUILTIN, HIGH);
    } else {
        digitalWrite(LED_BUILTIN, LOW);
    }
}

3.3 Analog Functions

analogRead()

int analogRead(uint8_t pin)

Reads analog voltage on an analog-capable pin. Uses the 12-bit SAR ADC, scaled to 10-bit for Arduino compatibility.

ParameterValuesDescription
pinA0 upwards, or the digital number of the same pinHow many channels there are, and which digital pin A0 is, are both device-specific — see §3.1.
Returns0 to 10230 = 0V, 1023 = 3.3V
// Example: Read temperature sensor on A0
int raw = analogRead(A0);             // 0-1023
float voltage = raw * (3.3 / 1023.0); // Convert to voltage
float tempC = voltage * 100.0;        // LM35: 10mV per degree C

// A0 is an alias for a digital pin, but not the same one on every device
// (see 3.1). Use the name A0 and the sketch stays portable.

dsPIC33CK32MP102 only — this is the device's own mapping, not a platform-wide one. The 256MC005 has 20 channels starting at A0 = D0; its table is Part 2 §2.2.

analogWrite() — PWM Output

void analogWrite(uint8_t pin, int val)

Outputs a PWM signal (for LED dimming, motor speed control). Uses SCCP peripheral modules.

ParameterValuesDescription
pina PWM-capable pinD5-D8 on all four devices; the 256MP508 adds D58. digitalPinHasPWM(p) tests it, and §3.1 lists the set per device.
val0 to 2550 = always off, 255 = always on, 128 = 50% duty
// Example: Fade an LED on D5 (RB0)
void loop() {
    // Fade up
    int i;
    for (i = 0; i <= 255; i += 5) {
        analogWrite(5, i);
        delay(30);
    }
    // Fade down
    for (i = 255; i >= 0; i -= 5) {
        analogWrite(5, i);
        delay(30);
    }
}

The SCCP mapping for D5-D8 is identical on all four devices — those four pins are RB0-RB3 everywhere:

PinSCCP ModulePPS Output
D5 (RB0)SCCP1 / OC1RP32
D6 (RB1)SCCP2 / OC2RP33
D7 (RB2)SCCP3 / OC3RP34
D8 (RB3)SCCP4 / OC4RP35
D58 (RE5) — 256MP508 onlySCCP5 / OC5RP181
On the 256MC005, analogWrite() is the SCCP pins only. D15-D20 and D35-D36 are MCPWM pins, which this core does not drive from analogWrite(); on those pins it falls through to a plain digitalWrite() of HIGH or LOW.

3.4 Timing Functions

millis()

unsigned long millis(void)

Returns the number of milliseconds since the program started. Overflows after ~49.7 days.

// Example: Non-blocking blink (no delay!)
unsigned long previousMillis = 0;
int ledState = LOW;

void loop() {
    unsigned long currentMillis = millis();
    if (currentMillis - previousMillis >= 1000) {
        previousMillis = currentMillis;
        ledState = !ledState;
        digitalWrite(LED_BUILTIN, ledState);
    }
    // Other code runs here without blocking!
}
Implementation: Uses Timer1 interrupt (fires every 1ms). The counter is read atomically using __builtin_disi() to disable interrupts briefly.

micros()

unsigned long micros(void)

Returns microseconds since program start. Resolution depends on clock speed (250ns at 4MHz FCY).

// Example: Measure execution time
unsigned long start = micros();
// ... code to measure ...
unsigned long elapsed = micros() - start;
Serial.print("Took ");
Serial.print(elapsed);
Serial.println(" microseconds");

delay()

void delay(unsigned long ms)

Pauses the program for the specified number of milliseconds. Blocking — no other code runs during the delay.

delay(1000);  // Wait 1 second
delay(500);   // Wait 0.5 seconds
delay(50);    // Wait 50 milliseconds

delayMicroseconds()

void delayMicroseconds(unsigned int us)

Pauses for the specified number of microseconds. Uses NOP cycle-counting (no interrupt dependency).

delayMicroseconds(10);   // 10 microsecond pause
delayMicroseconds(100);  // 100 microsecond pause
Warning: For delays > 16,000 microseconds, use delay() instead. Interrupts are NOT disabled during this function, so timing may vary slightly.

3.5 Serial (UART) Functions

What this Serial is: the Arduino IDE compiles the core and your sketch as C++ (xc-dsc-g++, with exceptions and RTTI off), so Serial is a class with the usual overloads — Serial.println(x), Serial.print(v, HEX), Serial.println(1.5, 2), bare Serial.println(). There is no String class in this core and no stream operator, so String(n) and Serial << x do not exist. Built as C instead — which is what the MPLAB X projects under cmake/ do — the same header gives Serial as a struct of function pointers, and only the suffixed numeric forms (Serial.print_int(v, HEX), Serial.println_float(x, 2)) are available. Both faces call the same serial_* functions.

Serial.begin()

void Serial.begin(unsigned long baud)

Initializes UART1 with the specified baud rate and configures its PPS pins automatically. Which pins those are is device-specific — see §3.1. On the dsPIC33CK256MC005 they are the two pads the on-board nEDBG bridges to USB CDC, so Serial reaches the Serial Monitor over the same USB cable with no extra wiring.

Baud RateCommon Use
9600Standard (reliable, slow)
19200Medium speed
38400Medium-fast
57600Fast
115200Fast (recommended for most use)
void setup() {
    Serial.begin(115200);  // Start serial at 115200 baud
    Serial.println("System ready!");
}

Serial.print() / Serial.println()

size_t Serial.print(const char *str)

size_t Serial.println(const char *str)

Sends a string over UART. println adds a newline (CR+LF) at the end.

Serial.print("Value: ");       // No newline
Serial.println("Hello!");      // With newline
Serial.print(42);     // Print number in decimal
Serial.print(255, HEX);    // Print "FF" (hex)
Serial.print(0b1010, BIN); // Print "1010" (binary)
Serial.println(analogRead(A0));  // Print ADC value

Serial.available() / Serial.read()

int Serial.available(void)

int Serial.read(void)

Check if data has been received and read one byte from the RX buffer.

// Example: Echo received characters
void loop() {
    if (Serial.available() > 0) {
        int c = Serial.read();    // Read one byte
        Serial.write((uint8_t)c); // Echo it back
    }
}

Serial.write()

size_t Serial.write(uint8_t c)

Sends a single raw byte over UART (no formatting).

Serial.write(0x41);  // Sends 'A'
Serial.write('\n');  // Sends newline character

3.6 Utility Functions

map()

long map(long value, long fromLow, long fromHigh, long toLow, long toHigh)

Re-maps a number from one range to another.

// Map ADC (0-1023) to PWM (0-255)
int adc = analogRead(A0);
int pwm = map(adc, 0, 1023, 0, 255);
analogWrite(5, pwm);

// Map sensor to angle (0-180 degrees)
int angle = map(adc, 0, 1023, 0, 180);

shiftOut() / shiftIn()

void shiftOut(uint8_t dataPin, uint8_t clockPin, uint8_t bitOrder, uint8_t val)

uint8_t shiftIn(uint8_t dataPin, uint8_t clockPin, uint8_t bitOrder)

Bit-bang serial communication (for shift registers like 74HC595).

// Example: Drive 74HC595 shift register
#define DATA_PIN  2   // RA2 - these three are RA2-RA4 on all four devices
#define CLOCK_PIN 3   // RA3
#define LATCH_PIN 4   // RA4

void setup() {
    pinMode(DATA_PIN, OUTPUT);
    pinMode(CLOCK_PIN, OUTPUT);
    pinMode(LATCH_PIN, OUTPUT);
}

void loop() {
    digitalWrite(LATCH_PIN, LOW);
    shiftOut(DATA_PIN, CLOCK_PIN, MSBFIRST, 0b10101010);
    digitalWrite(LATCH_PIN, HIGH);
    delay(500);
}
Changed in 1.0.6. This example used to use D11, D13 and D16, which are fine on the 32MP102 but wrong on the priority device: there D11 is RB6 = PGC3, an nEDBG debugger line, and D13 is the I2C SCL pin. If you copied the old version, move it to D2-D4.
