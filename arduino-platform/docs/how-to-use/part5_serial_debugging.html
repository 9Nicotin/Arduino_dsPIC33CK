How To Use Arduino_dsPIC33CK

Part 5: Serial Monitor & Debugging

5.1 Connect USB-Serial Adapter

1Wire the UART Connection


    dsPIC33CK32MP102              USB-to-Serial Adapter
    ┌────────────────┐            ┌───────────────┐
    │ RB5 (pin 14)   │───TX──────▶│ RX            │
    │   (Arduino D10) │            │               │
    │                 │            │               │
    │ RB4 (pin 11)   │◀──RX──────│ TX            │
    │   (Arduino D9)  │            │               │
    │                 │            │               │
    │ GND (pin 8)    │───GND─────│ GND           │
    └────────────────┘            └───────┬───────┘
                                          │
                                       [USB]
                                          │
                                     [Your PC]
Critical:
  • Cross TX/RX: dsPIC TX (RB5) → Adapter RX. dsPIC RX (RB4) → Adapter TX.
  • 3.3V Logic: Use a 3.3V adapter. 5V WILL damage the dsPIC!
  • Common GND: Always connect GND between board and adapter.

2Find the COM Port

  1. Plug in the USB-Serial adapter
  2. Open Device Manager (Win+X → Device Manager)
  3. Expand "Ports (COM & LPT)"
  4. Look for your adapter (e.g., "USB-SERIAL CH340 (COM3)")
  5. Note the COM number

5.2 Using Arduino IDE Serial Monitor

3Open Serial Monitor

  1. In Arduino IDE: Tools → Port → COMx (select your adapter port)
  2. Open: Tools → Serial Monitor (or press Ctrl+Shift+M)
  3. Set baud rate in the dropdown (bottom-right): match your code (e.g., 115200)
  4. Set line ending: "Both NL & CR"

4Example: Viewing Output

Upload this sketch:

#include "Arduino.h"
#include "HardwareSerial.h"

unsigned long count = 0;

void setup()
{
    Serial_begin(115200);
    Serial_println("=== Arduino_dsPIC33CK Ready ===");
}

void loop()
{
    count++;
    Serial_print("Tick #");
    Serial_print_int(count, DEC);
    Serial_print(" at ");
    Serial_print_int(millis(), DEC);
    Serial_println("ms");
    delay(1000);
}

You should see in Serial Monitor:

=== Arduino_dsPIC33CK Ready ===
Tick #1 at 102ms
Tick #2 at 1103ms
Tick #3 at 2104ms
Tick #4 at 3105ms
...

5Sending Data TO the dsPIC

Type text in the Serial Monitor input field (top) and press Enter or click "Send".

Your sketch receives it via Serial_available() and Serial_read():

#include "Arduino.h"
#include "HardwareSerial.h"

void setup()
{
    Serial_begin(115200);
    Serial_println("Type a command:");
    Serial_println("  '1' = LED ON");
    Serial_println("  '0' = LED OFF");
    pinMode(LED_BUILTIN, OUTPUT);
}

void loop()
{
    if (Serial_available() > 0) {
        int cmd = Serial_read();
        if (cmd == '1') {
            digitalWrite(LED_BUILTIN, HIGH);
            Serial_println("LED: ON");
        } else if (cmd == '0') {
            digitalWrite(LED_BUILTIN, LOW);
            Serial_println("LED: OFF");
        }
    }
}

5.4 Debugging Techniques

Technique 1: Print Debugging (Serial)

The simplest debugging method — add print statements to trace execution:

#include "Arduino.h"
#include "HardwareSerial.h"

void setup()
{
    Serial_begin(115200);
    Serial_println("[DEBUG] Starting setup...");

    pinMode(LED_BUILTIN, OUTPUT);
    Serial_println("[DEBUG] LED pin configured");

    /* Your initialization here */
    Serial_println("[DEBUG] Setup complete!");
}

void loop()
{
    Serial_println("[DEBUG] Entering loop");

    /* If program hangs, the last [DEBUG] line tells you where */
    doSomething();
    Serial_println("[DEBUG] After doSomething()");

    delay(1000);
}

Technique 2: LED Blink Codes

When Serial isn't available, use LED blink patterns:

/* Blink N times to indicate state/error */
void debugBlink(int count)
{
    int i;
    for (i = 0; i < count; i++) {
        digitalWrite(LED_BUILTIN, HIGH);
        delay(150);
        digitalWrite(LED_BUILTIN, LOW);
        delay(150);
    }
    delay(600);  /* Pause between patterns */
}

void setup()
{
    pinMode(LED_BUILTIN, OUTPUT);
    debugBlink(1);  /* 1 blink = setup started */

    /* ... init code ... */
    debugBlink(2);  /* 2 blinks = init done */
}

void loop()
{
    debugBlink(3);  /* 3 blinks = loop running */
    delay(2000);

    /* If you see 1 blink but never 2, problem is in init code
       If you see 2 but never 3, problem is between setup and loop */
}

Technique 3: Variable Monitoring

#include "Arduino.h"
#include "HardwareSerial.h"

void setup()
{
    Serial_begin(115200);
}

void loop()
{
    int adc = analogRead(A0);
    unsigned long time_ms = millis();
    int pin_state = digitalRead(2);

    /* Print all variables in one formatted line */
    Serial_print("[");
    Serial_print_int(time_ms, DEC);
    Serial_print("ms] ADC=");
    Serial_print_int(adc, DEC);
    Serial_print(" D2=");
    Serial_print_int(pin_state, DEC);
    Serial_println("");

    delay(200);
}

/* Output looks like:
   [1023ms] ADC=512 D2=1
   [1225ms] ADC=510 D2=1
   [1427ms] ADC=0   D2=0  <-- something happened!
*/

Technique 4: Direct Register Inspection

For hardware-level debugging, you can read and print dsPIC registers:

#include "Arduino.h"
#include "HardwareSerial.h"
#include <xc.h>

void setup()
{
    Serial_begin(115200);
    Serial_println("Register Dump:");

    Serial_print("  PORTA  = 0x");
    Serial_println_int(PORTA, HEX);

    Serial_print("  PORTB  = 0x");
    Serial_println_int(PORTB, HEX);

    Serial_print("  TRISA  = 0x");
    Serial_println_int(TRISA, HEX);

    Serial_print("  TRISB  = 0x");
    Serial_println_int(TRISB, HEX);

    Serial_print("  ANSELB = 0x");
    Serial_println_int(ANSELB, HEX);

    Serial_print("  T1CON  = 0x");
    Serial_println_int(T1CON, HEX);

    Serial_print("  PR1    = ");
    Serial_println_int(PR1, DEC);
}

void loop() { }

Settings for all terminals:

Baud rate:    115200 (or whatever your code uses)
Data bits:    8
Stop bits:    1
Parity:       None
Flow control: None

5.6 Tips for Effective Debugging

Debug Strategy:
  1. Start simple: Get Blink working first before adding complexity
  2. Add one thing at a time: Don't add Serial + ADC + PWM all at once
  3. Check hardware first: Use a multimeter to verify voltages and connections
  4. Read error messages carefully: The line number points to the exact problem
  5. Compare with examples: Use the working example sketches as reference
