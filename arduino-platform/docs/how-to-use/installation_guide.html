Arduino_dsPIC33CK - Installation Guide

Installing? Use the Boards Manager — no scripts, no path editing.

In Arduino IDE open File → Preferences → Additional Boards Manager URLs and add:

https://github.com/9Nicotin/Arduino_dsPIC33CK/releases/latest/download/package_microchip_dspic33ck_index.json

Then Tools → Board → Boards Manager, search for dsPIC33CK, and click Install. You still need the XC-DSC compiler v4.00+, plus MPLAB X if you upload with a PICkit 4 / SNAP / nEDBG: their licences forbid redistribution, so they cannot ship inside the platform and are located automatically when a build or upload runs. The Device Family Packs are redistributable and are installed for you.

Anything below that uses install_arduino_ide.bat or platform.local.txt is the developer path — it installs an edited working copy of this repo. A normal install needs neither. Windows only.

Complete setup guide: from a fresh Windows PC to blinking LEDs on your dsPIC33CK board

Quick Start (for experienced users)

If you already have Arduino IDE, the XC-DSC compiler v4.00+, and MPLAB X installed:

  1. File → Preferences → Additional Boards Manager URLs, add https://github.com/9Nicotin/Arduino_dsPIC33CK/releases/latest/download/package_microchip_dspic33ck_index.json
  2. Tools → Board → Boards Manager, search dsPIC33CK, click Install
  3. Tools → Board → select your dsPIC33CK board
  4. Done! Write your sketch and click Upload

No tool paths to configure: the Device Family Packs arrive with the install, and the compiler and MPLAB X are located automatically when you build or upload.

Working on the platform itself? Clone the repo and run arduino-platform\install_arduino_ide.bat instead — the Boards Manager can only install released archives, never your edited working tree.

1. Prerequisites

The platform itself comes from the Boards Manager. What you install by hand are the two Microchip tools it cannot legally redistribute:

#SoftwareVersionPurposeDownload
1 Arduino IDE 2.x Development environment (editor + build system) arduino.cc/en/software
2 XC-DSC Compiler v4.00+ Compiles your sketch. v4.00 is the first release with C++ (xc-dsc-g++), which this core requires — v3.31 cannot build it. microchip.com/xc-dsc
3 MPLAB X IDE v6.20+ (optional) Provides ipecmd.exe, used to upload via PICkit 4 / PICkit 5 / SNAP / PKOB4 / nEDBG. Skip it if you only compile, or if you upload over a UART bootloader. microchip.com/mplab
Why MPLAB X? You never open MPLAB X IDE itself. Arduino IDE uses exactly one file from it: ipecmd.exe, the command-line programmer for PICkit 4 / PICkit 5 / SNAP / PKOB4 / nEDBG.

The Device Family Packs are not in this list any more. They are Apache-2.0 licensed, so the Boards Manager ships them with the platform, pruned to the four supported devices — you no longer install them through MPLAB X, and there is no pack version to keep in step.

2. Install Prerequisites

1Install Arduino IDE 2.x

  1. Download from arduino.cc/en/software
  2. Run installer with default settings
  3. Launch Arduino IDE once to create the data folders, then close it

This creates: %LOCALAPPDATA%\Arduino15\ (where our platform will be installed)

2Install XC-DSC Compiler

  1. Download from microchip.com/xc-dsc
  2. Choose v4.00 or newer — earlier versions have no C++ compiler
  3. Run installer → Accept license → Install to default path
  4. The "Add to PATH" prompt does not matter: this platform calls the compiler by full path, and finds it whether or not it is on PATH

Default install location: C:\Program Files\Microchip\xc-dsc\v4.00\. Any v* directory under C:\Program Files\Microchip\xc-dsc\ is detected automatically, newest version first, so having several installed is fine.

The free edition is enough; it only limits optimization above -O1, which is the level this platform uses by default.

3Install MPLAB X IDE (only if you upload with a debugger)

  1. Download from microchip.com/mplab
  2. Run installer with default settings
  3. Close MPLAB X IDE when it finishes — you will not need to open it again

Any v* directory under C:\Program Files\Microchip\MPLABX\ is detected automatically, newest first, so several versions side by side are fine.

No Device Family Pack step. Earlier versions of this guide had you install dsPIC33CK-MP_DFP and dsPIC33CK-MC_DFP through Tools → Packs. That is no longer needed: the Boards Manager installs both packs, pruned to the supported devices, under %LOCALAPPDATA%\Arduino15\packages\microchip\tools\. Packs already in %USERPROFILE%\.mchp_packs\ are simply ignored by Arduino builds.

3. Install Arduino_dsPIC33CK Platform

4Install from the Boards Manager

  1. File → Preferences → Additional Boards Manager URLs (the field has a small button on its right that opens a one-URL-per-line editor), and add: 
    https://github.com/9Nicotin/Arduino_dsPIC33CK/releases/latest/download/package_microchip_dspic33ck_index.json
    Click OK.
  2. Open Tools → Board → Boards Manager and search for dsPIC33CK.
  3. Click Install. The download is under 1.5 MB: the platform plus the two pruned Device Family Packs.

Nothing else to configure. The compiler and MPLAB X are located when a build or upload actually runs, so no file needs your paths written into it.

That latest/download/ URL always resolves to the newest release, so future versions show up in the Boards Manager on their own.

Alternative: developer install (only if you are editing the platform)

The Boards Manager can only install released archives, never the working tree you are editing. Clone the repo and run arduino-platform\install_arduino_ide.bat instead — it copies your tree over the installed platform and checks your prerequisites. Re-run it after every source change.

What the developer installer does:
  1. Copies your working tree to %LOCALAPPDATA%\Arduino15\packages\microchip\hardware\dspic33ck\1.0.0\
  2. Verifies the copy, including the tools\bin\ compiler shims
  3. Reports the XC-DSC and MPLAB X versions a build would actually use, by calling the platform's own resolver — so what it prints is what the build gets
  4. Writes nothing at all when the Boards Manager DFP tool packs are present. Only if they are missing does it fall back to a two-line platform.local.txt pointing at your .mchp_packs copies, with a comment telling you to delete it once you have installed the released core
No manual path editing on either path.

Which programmer to select?

  • PICkit 4 / PICkit 5 — Standalone programmer connected via header
  • SNAP — MPLAB SNAP programmer
  • nEDBG — EV08P02A dsPIC33CK256MC005 Curiosity Nano (built-in)

7Test Compile

Paste this minimal blink sketch and click Verify (checkmark button):

#include <Arduino.h>

void setup() {
    pinMode(LED_BUILTIN, OUTPUT);
}

void loop() {
    digitalWrite(LED_BUILTIN, HIGH);
    delay(500);
    digitalWrite(LED_BUILTIN, LOW);
    delay(500);
}

If compilation succeeds with no errors — your installation is complete!

6. Troubleshooting

ProblemCauseSolution
Board not visible in Arduino IDE IDE was open during install Close ALL Arduino IDE windows, reopen
Installer shows [WARNING] for XC-DSC Compiler not installed or non-default path Install XC-DSC from microchip.com/xc-dsc
Installer shows [WARNING] for DFP Device Family Pack not installed Open MPLAB X → Tools → Packs → Install dsPIC33CK-MP_DFP
Compile error: "unknown device" Wrong DFP or DFP path mismatch Re-install from Tools → Board → Boards Manager. If a platform.local.txt exists next to platform.txt, a stale build.dfp.path in it will shadow the packs the install provides — delete the file.
Upload fails: "Could not connect" Programmer not detected Check USB cable, driver, and programmer selection in Tools menu
Device doesn't run after upload Missing -OL flag or config issue Update the platform from the Boards Manager (the -OL fix ships in it)

Manual Path Override

Only needed if you installed XC-DSC or MPLAB X somewhere other than C:\Program Files\Microchip\. Create this file (it does not exist after a Boards Manager install, and should not):

%LOCALAPPDATA%\Arduino15\packages\microchip\hardware\dspic33ck\1.0.0\platform.local.txt

Set only the keys you actually need — forward slashes, and a trailing slash on the compiler path:

# XC-DSC compiler bin/ directory
build.compiler.path=D:/tools/xc-dsc/v4.00/bin/

# MPLAB X IPE directory (for uploading)
build.tools.mplab.path=D:/tools/MPLABX/v6.35/mplab_platform/mplab_ipe

The environment variables XCDSC_PATH and MPLABX_IPE_PATH do the same job without editing any file.

Do not set build.dfp.path or build.dfp.path.mc here. They point at the Boards Manager tool packs. An override shadows the packs and goes stale the next time the platform updates — which shows up as a "cannot open linker script" or "CPU not recognized" error long after you wrote the line.

Restart Arduino IDE after saving changes.

7. What's in the arduino-platform Folder

arduino-platform/
├── install_arduino_ide.bat ← Developer install only (end users use the Boards Manager)
├── microchip/dspic33ck/
│   ├── platform.txt ← Build recipes (compiler, linker, bin2hex, upload)
│   ├── boards.txt ← Board definitions (MCU, clock, pins)
│   ├── cores/arduino/ ← Arduino API implementation (digitalWrite, delay, etc.)
│   ├── variants/ ← Pin mappings for each board
│   ├── tools/ ← Wrappers that locate the compiler and IPE at build time (xc-dsc-find.bat, link/size wrappers, upload)
│   ├── tools/bin/ ← Shims named after each compiler tool, so recipes call one path
│   └── programmers.txt ← Programmer definitions
└── docs/ ← Documentation (you are here)

Summary

To set up on a new computer:
  1. Install Arduino IDE 2.x and the XC-DSC compiler v4.00+ (plus MPLAB X, if you upload with a debugger)
  2. Arduino IDE → File → Preferences → Additional Boards Manager URLs, add the package_microchip_dspic33ck_index.json URL from the top of this page
  3. Tools → Board → Boards Manager → search dsPIC33CK → Install
  4. Select your board → compile → upload

No Device Family Pack to install, no folder to copy, no paths to configure.
