Arduino_dsPIC33CK User Guide

Part 1: Introduction & Setup

Installing? Use the Boards Manager — no scripts, no path editing.

In Arduino IDE open File → Preferences → Additional Boards Manager URLs and add:

https://github.com/9Nicotin/Arduino_dsPIC33CK/releases/latest/download/package_microchip_dspic33ck_index.json

Then Tools → Board → Boards Manager, search for dsPIC33CK, and click Install. You still need the XC-DSC compiler v4.00+, plus MPLAB X if you upload with a PICkit 4 / SNAP / nEDBG: their licences forbid redistribution, so they cannot ship inside the platform and are located automatically when a build or upload runs. The Device Family Packs are redistributable and are installed for you.

Anything below that uses install_arduino_ide.bat or platform.local.txt is the developer path — it installs an edited working copy of this repo. A normal install needs neither. Windows only.

1.1 What is Arduino_dsPIC33CK?

Arduino_dsPIC33CK is a custom Arduino-compatible platform that lets you program Microchip dsPIC33CK digital signal controllers using the familiar Arduino programming style. Four devices ship with board support: dsPIC33CK256MC005 (Curiosity Nano — the device this platform is developed against), dsPIC33CK256MP508 (Curiosity), dsPIC33CK256MC002 and dsPIC33CK32MP102. Pin numbers, pin counts and LED_BUILTIN differ between them — Part 3 §3.1 has the per-device table, and every page that shows one board's numbers says which board.

Instead of writing complex register-level code like this:

// Traditional dsPIC33CK code (complex)
TRISAbits.TRISA0 = 0;      // Set RA0 as output
LATAbits.LATA0 = 1;        // Set RA0 high
T1CONbits.TON = 1;         // Start timer
// ... many more register manipulations

You can write simple Arduino-style code:

// Arduino_dsPIC33CK code (simple)
pinMode(LED_BUILTIN, OUTPUT);
digitalWrite(LED_BUILTIN, HIGH);
delay(1000);

How It Works (Architecture)


  +---------------------------+
  |   Your Arduino Sketch     |   <-- You write this (setup/loop)
  |   (Blink.ino)             |
  +---------------------------+
             |
             v
  +---------------------------+
  |   Arduino Core API        |   <-- Arduino_dsPIC33CK provides this
  |   (Arduino.h)             |
  |   digitalWrite()          |
  |   analogRead()            |
  |   millis()                |
  |   Serial.print()          |
  +---------------------------+
             |
             v
  +---------------------------+
  |   dsPIC33CK Hardware      |   <-- Registers, peripherals
  |   Abstraction Layer       |
  |   (variant.c, pin_map)    |
  +---------------------------+
             |
             v
  +---------------------------+
  |   XC-DSC Compiler v4.00+  |   <-- Compiles to dsPIC machine code
  +---------------------------+
             |
             v
  +---------------------------+
  |   Your dsPIC33CK MCU      |   <-- Physical hardware
  +---------------------------+

1.2 What You Need (Prerequisites)

Item Required? Download / Notes
XC-DSC Compiler v4.00+ YES microchip.com/xc-dsc — free edition is enough; v4.00 is the first with C++, which this core requires
MPLAB X IDE v6.20+ YES for debugger uploads microchip.com/mplab — every upload through a debugger runs Microchip's ipecmd, which ships with MPLAB X. That includes the on-board nEDBG and PKOB4. Only the serial bootloader path (Part 6) works without it.
Device Family Packs (MP_DFP and MC_DFP) YES The Boards Manager installs both for you — they are redistributable. In MPLAB X, use Tools → Packs: dsPIC33CK-MP_DFP for the MP parts, dsPIC33CK-MC_DFP for the MC parts.
PICkit 4, PICkit 5 or MPLAB SNAP Only for a bare board External ICSP debugger. You do not need one for the dsPIC33CK256MC005 Curiosity Nano (on-board nEDBG) or the dsPIC33CK256MP508 Curiosity (on-board PKOB4) — on those the debugger is on the board and shares the one USB cable.
A dsPIC33CK board YES dsPIC33CK256MC005 Curiosity Nano (EV08P02A), dsPIC33CK256MP508 Curiosity (DM330030), or your own board carrying any of the four supported devices
USB-to-UART adapter Only on a bare board FTDI, CP2102, CH340 — any 3.3 V adapter. Not needed on the two Curiosity boards: their on-board debugger also presents a CDC COM port, so the Serial Monitor works over the same cable.
Python 3.8+ For serial upload python.org — only for the serial bootloader path, which is offered on the dsPIC33CK256MC005 today. No pip packages are needed; the uploader is standard library only.
LED + 330 ohm resistor Only on a bare board Standard through-hole components. The two Curiosity boards already have an LED on LED_BUILTIN (and on the Curiosity Nano it is wired active LOW).
IMPORTANT: 3.3V ONLY!
Every dsPIC33CK device on this platform runs at 3.3 V. Do NOT connect 5V signals to any pin. If using a USB-Serial adapter, ensure it supports 3.3V logic levels.

1.3 Installation

Three steps, and only the first involves a download from Microchip. If you would rather follow a screenshot-by-screenshot walkthrough of the Arduino IDE itself, use the Arduino IDE setup guide instead — it covers the same ground in more detail.

1Install the XC-DSC Compiler

  1. Download XC-DSC v4.00 or newer from microchip.com/xc-dsc
  2. Run the installer (accept defaults)
  3. Default path: C:\Program Files\Microchip\xc-dsc\v4.00\
  4. No PATH change needed — the platform locates any v* directory under C:\Program Files\Microchip\xc-dsc\ when a build runs, newest first

Verify installation — open Command Prompt and type:

"C:\Program Files\Microchip\xc-dsc\v4.00\bin\xc-dsc-gcc.exe" --version

Expected output: xc-dsc-gcc (Microchip XC-DSC ... v4.00) .... Use the full path: XC-DSC is not added to PATH, and the platform does not need it to be. v4.00 is the first release with C++, which this core requires.

2Install the platform from the Boards Manager

  1. In the Arduino IDE open File → Preferences → Additional Boards Manager URLs and add the URL in the green banner at the top of this page
  2. Open Tools → Board → Boards Manager, search for dsPIC33CK, and click Install
  3. Restart the IDE if the boards do not appear immediately

That one install brings the four boards, both Device Family Packs, the core, the libraries (SPI, Wire, HRPWM, Arduino_dsPIC33CK), the example sketches under File → Examples, and this guide. It lands in:

%LOCALAPPDATA%\Arduino15\packages\microchip\
Working on the platform itself? A clone of the repository has the same tree under arduino-platform\, and install_arduino_ide.bat installs that working copy over the top. That is the developer path; a normal install needs neither it nor platform.local.txt.

What is in the platform folder:

microchip/dspic33ck/
├── boards.txt                 (the four boards and their menus)
├── platform.txt               (compiler and upload recipes)
├── programmers.txt            (PICkit 5/4, SNAP, PKOB4, nEDBG, bootloader)
├── cores/arduino/             (the Arduino API sources)
├── variants/                  (one pin map per device)
│   ├── dspic33ck256mc005/     (Curiosity Nano)
│   ├── dspic33ck256mp508/     (Curiosity)
│   ├── dspic33ck256mc002/
│   └── dspic33ck32mp102/
├── libraries/                 (SPI, Wire, HRPWM, Arduino_dsPIC33CK + examples)
├── bootloaders/               (serial bootloader sources and HEX, MC005)
├── ldscripts/                 (bootloader-aware linker scripts)
└── tools/                     (upload and compiler-locator scripts)

3Install MPLAB X — unless you only ever upload over serial

  1. Download from microchip.com/mplab
  2. Install with default options

Uploading through a debugger — an external PICkit or SNAP, or the on-board nEDBG / PKOB4 — runs Microchip's ipecmd, which comes with MPLAB X. The Device Family Packs arrive with the platform, so you do not need to add them by hand for an Arduino IDE build; install them from Tools → Packs only if you also build MPLAB X projects.

Skip this step only if you will upload exclusively with the serial bootloader (Part 6) — note that burning the bootloader in the first place needs a debugger, so on a bare board you need one at least once.

4Build and upload your first sketch

  1. Tools → Board → Arduino_dsPIC33CK → your board
  2. Tools → Clock — leave it at 8 MHz Internal FRC for now; 200 MHz PLL is the fast option
  3. Tools → Port — pick the board's COM port
  4. File → Examples → Arduino_dsPIC33CK → Blink
  5. Click Upload (→), or Sketch → Upload Using Programmer if you are using an external PICkit or SNAP

On the Curiosity Nano the LED is LED_BUILTIN = D37 and is wired active LOW, so digitalWrite(LED_BUILTIN, LOW) lights it. Part 3 §3.1 gives the pin for each board; Part 5 is where to go if the upload fails.

1.4 Legacy path: building in MPLAB X by hand

You do not need any of this to use the platform. It is kept for two reasons: bringing the core up in an MPLAB X project is how the debugger and the peripheral registers are best examined, and it is what the repository's cmake/ projects do. If you installed from the Boards Manager, skip to Part 2.

The steps below use the dsPIC33CK256MC005; substitute your device name and its variants/ folder throughout.

L1Create the project

  1. Open MPLAB X → File → New Project
  2. Select Microchip Embedded → Standalone Project
  3. Device: dsPIC33CK256MC005
  4. Tool: the debugger your board has — nEDBG on the Curiosity Nano, PKOB4 on the Curiosity, otherwise your PICkit
  5. Compiler: XC-DSC (v4.00 or newer)
  6. Project Name: Arduino_dsPIC33CK_Test

L2Add the core files

Right-click "Source Files" → Add Existing Items From Folders.

Source files (.c) — all of them. Leaving out wiring_interrupts.c or wiring_tone.c builds fine until the first sketch that calls attachInterrupt() or tone(), which then fails at link time:

microchip/dspic33ck/cores/arduino/main.c
microchip/dspic33ck/cores/arduino/system_config.c
microchip/dspic33ck/cores/arduino/wiring.c
microchip/dspic33ck/cores/arduino/wiring_digital.c
microchip/dspic33ck/cores/arduino/wiring_analog.c
microchip/dspic33ck/cores/arduino/wiring_shift.c
microchip/dspic33ck/cores/arduino/wiring_interrupts.c
microchip/dspic33ck/cores/arduino/wiring_tone.c
microchip/dspic33ck/cores/arduino/HardwareSerial.c
microchip/dspic33ck/variants/dspic33ck256mc005/variant.c

Header files (.h):

microchip/dspic33ck/cores/arduino/Arduino.h
microchip/dspic33ck/cores/arduino/system_config.h
microchip/dspic33ck/cores/arduino/HardwareSerial.h
microchip/dspic33ck/cores/arduino/wiring_private.h
microchip/dspic33ck/variants/dspic33ck256mc005/pins_arduino.h
C, not C++, on this path. An MPLAB X project compiles these as C, and HardwareSerial.h then presents Serial as a struct of function pointers: Serial.print_int(v, HEX) rather than the overloaded Serial.print(v, HEX) you get from the Arduino IDE's C++ build. Both call the same underlying functions — see Part 3 §3.5.

L3Configure include paths and macros

Right-click Project → Properties → XC-DSC (Global Options) → xc-dsc-gcc → Preprocessing and messages

Add include directories:

../arduino-platform/microchip/dspic33ck/cores/arduino
../arduino-platform/microchip/dspic33ck/variants/dspic33ck256mc005

Add preprocessor macros in the same page. These are the values the default clock menu passes, so a project defining them behaves like an IDE build with Tools → Clock → 8 MHz Internal FRC:

F_CPU=8000000UL
FCY=4000000UL
ARDUINO_DSPIC33CK256MC005

For the fast option use F_CPU=200000000UL and FCY=100000000UL instead; the core brings the PLL up at run time. The two must agree with each other or delay(), millis() and the Serial baud rate will all be wrong by the same factor.

L4Write the sketch

Create a new file called sketch.c in your project's Source Files:

/* sketch.c - Your Arduino sketch */
#include "Arduino.h"

void setup()
{
    pinMode(LED_BUILTIN, OUTPUT);
}

void loop()
{
    digitalWrite(LED_BUILTIN, HIGH);
    delay(1000);
    digitalWrite(LED_BUILTIN, LOW);
    delay(1000);
}
Note: Do NOT include your own main() function. The Arduino core's main.c already handles calling setup() once and loop() repeatedly. LED_BUILTIN comes from the variant header, so it is D37 here and a different pin on another board — on the Curiosity Nano it is active LOW, so this sketch's HIGH phase is the LED's off phase.

L5Build and program

  1. Click Build (hammer icon) or press F11
  2. Fix any errors (see Part 5)
  3. Connect the debugger — on the two Curiosity boards it is on the board and needs only the USB cable; otherwise wire your PICkit to the ICSP header
  4. Click Make and Program Device (down-arrow icon)
  5. Watch the LED blink
Programming through a debugger erases the whole device, including a serial bootloader if one was burned. Re-burn it with Tools → Burn Bootloader afterwards.

1.5 MPLAB X project structure

For the legacy path above, the finished project looks like this. An Arduino IDE build needs none of it — the IDE compiles the core out of the installed platform folder.

Your MPLAB X Project/
├── Source Files/
│   ├── sketch.c              <-- YOUR CODE (setup + loop)
│   ├── main.c                <-- Arduino entry point (DO NOT EDIT)
│   ├── system_config.c       <-- Clock & config bits
│   ├── wiring.c              <-- millis/delay
│   ├── wiring_digital.c      <-- GPIO functions
│   ├── wiring_analog.c       <-- ADC & PWM
│   ├── wiring_shift.c        <-- shiftOut/In
│   ├── wiring_interrupts.c   <-- attachInterrupt
│   ├── wiring_tone.c         <-- tone/noTone
│   ├── HardwareSerial.c      <-- UART Serial
│   └── variant.c             <-- Pin lookup table
├── Header Files/
│   ├── Arduino.h             <-- Main API (include this)
│   ├── system_config.h
│   ├── HardwareSerial.h
│   ├── wiring_private.h
│   └── pins_arduino.h        <-- Pin definitions
└── Important Files/
    └── (linker script auto-selected by compiler)
