Arduino_dsPIC33CK

Arduino IDE Setup & Usage Guide

Installing? Use the Boards Manager — no scripts, no path editing.

In Arduino IDE open File → Preferences → Additional Boards Manager URLs and add:

https://github.com/9Nicotin/Arduino_dsPIC33CK/releases/latest/download/package_microchip_dspic33ck_index.json

Then Tools → Board → Boards Manager, search for dsPIC33CK, and click Install. You still need the XC-DSC compiler v4.00+, plus MPLAB X if you upload with a PICkit 4 / SNAP / nEDBG: their licences forbid redistribution, so they cannot ship inside the platform and are located automatically when a build or upload runs. The Device Family Packs are redistributable and are installed for you.

Anything below that uses install_arduino_ide.bat or platform.local.txt is the developer path — it installs an edited working copy of this repo. A normal install needs neither. Windows only.

Prerequisites before starting:
  • Arduino IDE 2.x installed (download here)
  • Microchip XC-DSC compiler v4.00+ installed (download here)
  • MPLAB X IDE installed — every debugger upload calls its ipecmd, including the on-board nEDBG / PKOB debuggers on the two Curiosity boards. The one path that does not need it is a serial-bootloader upload (Part 6)

Step 1: Install the Platform

1Add the Boards Manager URL

  1. Open Arduino IDE 2.x
  2. Go to File → Preferences
  3. In Additional Boards Manager URLs, paste: 
    https://github.com/9Nicotin/Arduino_dsPIC33CK/releases/latest/download/package_microchip_dspic33ck_index.json
  4. Click OK

2Install from the Boards Manager

  1. Go to Tools → Board → Boards Manager
  2. Search for dsPIC33CK
  3. Click Install

What this does: downloads the platform and the two pruned Device Family Packs into:
%LOCALAPPDATA%\Arduino15\packages\microchip\

No path configuration. There is no platform.local.txt to edit. The XC-DSC compiler and MPLAB X are located automatically when a build or upload runs — including choosing the newest of several installed versions — and the Device Family Packs come from the Boards Manager itself.

3Check the Prerequisites

Two Microchip tools stay user-installed, because their licences are non-transferable and forbid redistribution:

ToolNeeded forNotes
XC-DSC v4.00+ compiling v4.00 is the first with C++ (xc-dsc-g++), which this core requires. The free edition is enough. It does not need to be on PATH.
MPLAB X IDE upload via PICkit 4 / SNAP / nEDBG Not needed to compile, or to upload over the UART bootloader.

Installed somewhere other than C:\Program Files\Microchip\? Then — and only then — create a platform.local.txt next to the installed platform.txt with build.compiler.path= and/or build.tools.mplab.path=.

Developing this platform? The Boards Manager can only install released archives, never your working tree, so contributors run arduino-platform\install_arduino_ide.bat from a clone instead. It copies the edited tree over the installed platform and re-checks the prerequisites; re-run it after every source change. Everyone else can ignore it.

Step 2: Select the Board in Arduino IDE

4Open Arduino IDE and Select Board

  1. Open Arduino IDE 2.x
  2. Go to Tools → Board
  3. Pick your board. Four are listed: dsPIC33CK256MC005 Curiosity Nano, dsPIC33CK256MC002, dsPIC33CK32MP102 and dsPIC33CK256MP508. The rest of this page uses the dsPIC33CK256MC005 Curiosity Nano, because it needs no wiring at all.
  4. If you don't see it, restart Arduino IDE
Tools Menu, with the Curiosity Nano selected: +-----------------------------------------------------------------+ | Board: "Arduino_dsPIC33CK (dsPIC33CK256MC005 Curiosity | | Nano)" | | Clock: "8 MHz Internal FRC (Default)" | | Bootloader: "None (upload with the debugger)" | | Programmer: "nEDBG (Curiosity Nano On-Board)" | | Port: "COM3" | +-----------------------------------------------------------------+ The Bootloader entry appears on the dsPIC33CK256MC005 only. Leave it at "None" until you have actually burned the bootloader.

5Select Clock Speed

Go to Tools → Clock and choose:

OptionFOSCFCYUse Case
8 MHz Internal FRC (Default)8 MHz4 MHzLow power, simple projects
200 MHz PLL200 MHz100 MHzHigh performance, fast ADC/PWM

The menu sets the F_CPU and FCY macros; the PLL itself is brought up at run time by the core, which always starts on the FRC. On the dsPIC33CK256MP508 a third entry, "200 MHz PLL (alias)", exists only so sketches saved against the older clock=100mhz_pll identifier still build — it produces exactly the same clock as "200 MHz PLL".

6Select Programmer

Go to Tools → Programmer and choose the one your board has:

ProgrammerWhen to Use
nEDBG (Curiosity Nano On-Board)the dsPIC33CK256MC005 Curiosity Nano — already on the board, on the same USB cable as the Serial Monitor
PKOB4 (Curiosity On-Board)the dsPIC33CK256MP508 Curiosity board — likewise on-board
PICkit 4a board of your own, wired to the ICSP header
PICkit 5same, with the newer tool
MPLAB SNAPsame, cheaper tool; no high-voltage MCLR
Serial Bootloader (UART)dsPIC33CK256MC005 with the bootloader already burned, and the sketch built with Tools → Bootloader: "Serial (UART, 115200)". With that menu option selected, plain Upload already takes this path — the entry is only for using it while some other programmer is the default
Upload vs Upload Using Programmer. Upload (Ctrl+U) uses the board's own default, which is the on-board debugger on both Curiosity boards. Sketch → Upload Using Programmer is what forces the selection above.

Step 3: Write Your First Sketch

7Create a New Sketch

Go to File → New Sketch. Replace the contents with:

/*
 * Blink - Arduino_dsPIC33CK
 *
 * LED_BUILTIN is whichever pin your board defines: D37 (RD10) on the
 * dsPIC33CK256MC005 Curiosity Nano, D59 (RE6) on the dsPIC33CK256MP508
 * Curiosity board, and D0 (RA0) as a bare default on the other two, where you
 * wire your own LED. Part 3 section 3.1 has the table.
 *
 * NOTE: XC-DSC v4.00+ compiles this core as C++, so ordinary Arduino syntax works:
 *   - Serial.print(value, HEX), Serial.println(1.5, 2) and the other overloads
 *   - Classes, templates and overloading are available
 *   - But there is no String class and no new/delete
 */
#include "Arduino.h"

void setup()
{
    pinMode(LED_BUILTIN, OUTPUT);
}

void loop()
{
    digitalWrite(LED_BUILTIN, HIGH);
    delay(1000);
    digitalWrite(LED_BUILTIN, LOW);
    delay(1000);
}

Save it as Blink_dsPIC33CK (File → Save As)

On the dsPIC33CK256MC005 the on-board LED is active LOW — HIGH turns it off, LOW turns it on. The sketch still blinks; the half-second the code calls "on" is the dark one. The variant defines LED_BUILTIN_ACTIVE_LOW so a sketch can test for it.
Critical Rules When Writing Sketches:
  1. Always include #include "Arduino.h" at the top
  2. Serial needs no extra include: Arduino.h already pulls in HardwareSerial.h
  3. C++ is available (classes, templates, overloading), but this core provides no String class, no new/delete, no exceptions and no RTTI
  4. Declare variables wherever you like, for (int i = 0; ...) included
  5. Do NOT write your own main() — only setup() and loop()

Step 4: Build (Verify)

8Click Verify (Compile)

  1. Click the checkmark button (✓) in the toolbar, or press Ctrl+R
  2. Watch the Output panel at the bottom
Output: Compiling sketch... "...\tools\bin\xc-dsc-g++.bat" -mcpu=33CK256MC005 -x c++ ... Compiling core... Linking everything together... "...\tools\xc-dsc-size-wrapper.bat" sketch.elf Sketch uses 2048 bytes (6%) of program storage space. Global variables use 128 bytes (3%) of dynamic memory. Done compiling.
If build succeeds: You'll see "Done compiling." and memory usage.

Step 5: Upload to Hardware

9Upload

Curiosity Nano or Curiosity board: the debugger is already on the board, so there is nothing to connect but the USB cable.

  1. Select the board's port under Tools → Port
  2. Click the Upload button (→ arrow) or press Ctrl+U
  3. Arduino IDE calls ipecmd through the on-board debugger

A board of your own: wire a PICkit 4 / 5 or SNAP to the ICSP header (MCLR, VDD, GND, PGD, PGC — see Part 5 §5.1 for which PGD/PGC pair your board selects), choose it under Tools → Programmer, then use Sketch → Upload Using Programmer.

Uploading to a dsPIC33CK256MC005 Curiosity Nano... "C:/Program Files/Microchip/MPLABX/v6.20/mplab_platform/bin/ipecmd.exe" -TPnEDBG -PdsPIC33CK256MC005 -M -F"sketch.hex" Connecting to nEDBG... Device ID verified: dsPIC33CK256MC005 Erasing... Programming... Verify... Done. Upload complete.
A silent COM port straight after an upload is not a dead sketch. Programming through the nEDBG can leave its USB-CDC bridge wedged. Unplug the board and plug it back in before suspecting your code.

Step 6: Using Serial Monitor

10Open Serial Monitor for UART Output

On the dsPIC33CK256MC005 Curiosity Nano and the dsPIC33CK256MP508 Curiosity board, the on-board debugger also provides a USB-CDC serial bridge, so Serial reaches the Serial Monitor over the same cable that programmed the board. On a board of your own, wire a 3.3 V USB-UART adapter to the variant's Serial pins first. Then:

  1. Select the correct COM port: Tools → Port → COMx
  2. Open Serial Monitor: Tools → Serial Monitor or Ctrl+Shift+M
  3. Set baud rate to match your code (e.g., 115200)
/* Example sketch with Serial */
#include "Arduino.h"

void setup()
{
    pinMode(LED_BUILTIN, OUTPUT);
    Serial.begin(115200);
    Serial.println("Hello from Arduino_dsPIC33CK!");
}

void loop()
{
    int adc = analogRead(A0);
    Serial.print("ADC: ");
    Serial.println(adc);
    delay(500);
}
Which COM port? On the two Curiosity boards the debugger and the CDC bridge are the same USB device, so one port does both and Tools → Port is all you set. With an external PICkit the monitor port belongs to your USB-UART adapter, not to the PICkit, and the two are different ports. Which pins the adapter goes to is per device — RC10/RC11 on the dsPIC33CK256MC005, RB5/RB4 on the dsPIC33CK32MP102 and dsPIC33CK256MC002; see Part 3 §3.1.

Troubleshooting Arduino IDE Issues

ProblemSolution
Board not visible in Tools menu Re-install from Tools → Board → Boards Manager, then restart Arduino IDE completely (close all windows). Developer installs: re-run install_arduino_ide.bat.
"XC-DSC compiler not found" Install XC-DSC v4.00+. It is found automatically and does not need to be on PATH. Only if it lives outside C:\Program Files\Microchip\, set build.compiler.path in platform.local.txt.
C++ features rejected, or xc-dsc-g++.exe missing Your XC-DSC predates v4.00. C++ (classes, templates, overloading) is supported from v4.00 on, and this core requires it — upgrade the compiler. There is still no String class and no new/delete.
"undefined reference to _setup" Your sketch must have void setup() and void loop() functions.
Upload fails: "ipecmd not found" Install MPLAB X. It is located automatically, including picking the newest of several installed versions. Only if it lives outside C:\Program Files\Microchip\, set build.tools.mplab.path in platform.local.txt.
Upload fails: "Target not found" Check PICkit4 connection. Ensure MCLR, VDD, GND, PGD, PGC wired correctly.
Serial Monitor shows nothing after an upload Unplug the board and plug it back in: programming through the on-board debugger can leave its USB-CDC bridge wedged. If output is garbled instead, the baud rates do not match, or the sketch was built for a different clock.
Tip: If you get stuck, you can always fall back to MPLAB X IDE, which has full native support for XC-DSC and dsPIC33CK. The Arduino IDE integration is a convenience layer — MPLAB X gives you the debugger, breakpoints, and register views.
