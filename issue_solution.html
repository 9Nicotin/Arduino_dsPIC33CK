Issue Solution: Arduino IDE Build Not Working on dsPIC33CK256MP508

Date: 2024-06-11 | Board: DM330030 Curiosity Development Board | Device: dsPIC33CK256MP508

Summary

LED blink sketch compiled and uploaded successfully from Arduino IDE, but the device would not run. The same source code compiled from command line worked perfectly. The issue was in the hex file generation step.

Root Cause

Missing -mdfp flag in xc-dsc-bin2hex

The recipe.objcopy.hex.pattern in platform.txt did NOT pass the -mdfp (Device Family Pack) path to xc-dsc-bin2hex.exe. Without this flag, the tool generates configuration word records at incorrect hex addresses (Extended Address segment 0x0002), which ipecmd misinterprets as program memory instead of configuration registers.

What Happened Internally

Step Without -mdfp (BROKEN) With -mdfp (WORKING)
bin2hex config output Segment 0x0002, address 0xBFxx Segment 0x0005, address 0x7Exx
ipecmd interpretation Treats as program memory at 0x15800-0x15FFF Treats as configuration memory (correct registers)
Device config after programming Erased defaults (wrong clock, watchdog ON, DMT active) Correct values (FRC clock, WDT software, DMTDIS=ON, ICS=PGD3)
Result Device does not run LEDs blink correctly

ipecmd Output Comparison

BROKEN (config written to wrong location):

program memory: start address = 0x0, end address = 0x7ff
program memory: start address = 0x15800, end address = 0x15fff   <-- BAD! This is config data misplaced
configuration memory

FIXED (config written to correct registers):

program memory: start address = 0x0, end address = 0x7ff
configuration memory   <-- Config correctly identified

The Fix

platform.txt line 95 — Add -mdfp={build.dfp.path} to bin2hex recipe

Before (broken):

recipe.objcopy.hex.pattern="{runtime.platform.path}/tools/suppress-stderr.bat" "{compiler.path}xc-dsc-bin2hex.exe" "{build.path}/{build.project_name}.elf"

After (fixed):

recipe.objcopy.hex.pattern="{runtime.platform.path}/tools/suppress-stderr.bat" "{compiler.path}xc-dsc-bin2hex.exe" -mdfp={build.dfp.path} "{build.path}/{build.project_name}.elf"

Other Fixes Applied During Investigation

IssueFixFile
ipecmd holds device in reset after programming Added -OL flag (Release from Reset) to all programmer tools platform.txt (tools.pkob4/pickit4/pickit5/snap patterns)
Boot config pragmas cause "address 0x400C00 doesn't exist" error Removed BTMODE/BSEN/BSS/GWRP/GSS/CWRP/CSS pragmas (leave at erased defaults) cores/arduino/system_config.c
FWDTEN = OFF invalid for dsPIC33CK256MP508 Changed to FWDTEN = ON_SW system_config.c
Dead Man Timer resetting device Set DMTDIS = ON (disable DMT) system_config.c

Key Lessons

  • Always pass -mdfp to ALL XC-DSC tools — not just the compiler and linker, but also bin2hex. Without it, the tool lacks device-specific knowledge of configuration word address mapping.
  • The suppress-stderr.bat wrapper hides warnings — bin2hex printed "Could not open resource file" to stderr (which was suppressed), silently falling back to incorrect address mapping.
  • ipecmd "program memory: 0x15800" is a red flag — for single-partition dsPIC33CK256MP508, configuration memory should never appear as program memory. This indicates config words are at wrong hex addresses.
